## Purpose / Big Picture

Two families of real Bifrost regressions cannot be expressed as RQL queries or RQLP assertions today.

The first family is *premature state use*: a resolver or analysis treats a binding or object property as available at a program point where control flow has not yet established it, or keeps using it after a kill or rebind. Source-file co-presence and naive source order are the wrong evidence: an assignment later in the file, in a dead branch, or in the same evaluation as the read must not count as establishment. Today RQL has `reaching-binding` (from #1474), but that relation is *lexical*: it answers "which declaration does this name bind to under scoping rules", not "has any assignment to this binding executed before this read". Nothing in RQL can state "this property read is dominated by an establishment write" or "this read and that write occur in the same evaluation and therefore the write cannot serve the read".

The second family is *unbounded structured rewrite*: an analyzer chases a chain of rewrites (import-alias substitution, specifier rewriting, type-inference delegation) that is supposed to converge, and a cyclic input makes it loop or recurse forever. The fix pattern is always the same: make the chase iterative, bound it by the finite domain it walks, detect a repeated semantic state, and stop with an explicit outcome. Today none of that is visible to RQL: there is no way to enumerate a rewrite chain as rows, no way to assert that a supported rewrite domain converges within its declared bound, and no way to distinguish "converged", "concrete cycle detected" and "budget exhausted, unknown".

The four mined commits in the issue inventory are exactly these shapes:

- `9e60fddcb` "Keep JavaScript dotted lookup receiver-exact": an assignment-created property may only serve a member reference when the assignment *precedes the reference in the same structured lexical scope*. This is a hand-written flow-order rule inside `crates/bifrost-analysis/src/analyzer/usages/get_definition/js_ts.rs`; the capability this plan builds would let a conformance rule assert that ordering instead of trusting each resolver to re-implement it.
- `671e9b23b` "Reject unbound JavaScript namespace assignment artifacts": a namespace-assignment artifact must not act as an established binding at reference sites it never reaches. Same file, same shape: availability follows value flow, not co-presence.
- `edb00e017` "Make Go range inference stack safe": a `range` iterable must be evaluated at its own lexical source position so a same-named range variable is not visible in its own right-hand side; the self-visible binder made inference recurse forever. This is the *same-evaluation* relation (a binder introduced by a statement is not available inside that statement's own evaluation) plus a termination bug.
- `9deded6f5` "rust: stop resolve_module_package alias chase from looping on rename cycles": the import-alias chase in what is now `crates/bifrost-rust/src/imports.rs` rewrote a specifier root through the binder map forever when renames formed a cycle (`use a::b as c;` plus `use c::d as a;`). The fix keyed the visited set on the *semantic state* (the root, because the specifier text grows every hop and can never repeat), bounded the walk by the binder's root count, and stopped with an explicit terminal status. That fix's structure — semantic state key, per-step provenance, repeated-state detection, declared finite bound, explicit converged/cycle/exceeded outcome — is precisely the row contract this plan exposes.

After this change, four things work that do not work today:

1. RQL can enumerate *binding/property state events* as source-backed typed rows inside a procedure: establishment (assignment, declaration initialization, property creation), kill/rebind (reassignment, shadowing redeclaration, delete), and read, each anchored to a program point of the production CFG with the same `ast_id` join currency every other row family uses.
2. RQL can relate those events with flow relations carrying exact/may certainty: reaching-definition (which establishments can reach this read along some CFG path, with `exact` when all paths agree and `may` otherwise), dominance (every path from entry to the read passes the establishment), and same-evaluation (the read sits inside the very statement whose binder it names, so the binder cannot serve it). Structural containment and textual order are never presented as any of these; a query that asks for a flow relation on a language axis without CFG evidence gets a typed unsupported diagnostic, not a lexical approximation.
3. RQL can enumerate *bounded rewrite paths* for supported finite rewrite domains (first domain: the Rust import-alias/specifier rewrite chase) as rows: each step names its input state, its output state, the rule that fired, and the semantic state key; the path row states the declared bound, the work performed, and the outcome — `converged` with the fixed point, `cycle` with the ordered repeated-state witness, or `exceeded-budget` with what was explored. Budget exhaustion is not evidence of anything.
4. The RQLP `assertion` analysis kind gains temporal and termination asserts: a policy can require that every read of a captured binding/property is dominated by (or at least reached by) an establishment, that a read is never served by a same-evaluation binder, and that a supported rewrite domain universally terminates within its declared bound on the workspace's actual inputs. Findings carry ordered witnesses (the CFG path or the rewrite step sequence). Any incompleteness — no CFG lowering for the language, an unsupported event axis, budget exhaustion, analysis diagnostics — yields `unreliable` / `Inconclusive`, never a clean pass and never a finding.

Non-goals, restated from the issue so no reader over-claims: this surface does not prove arbitrary-program termination and does not claim stack safety of analyzer code. It is bounded and relation-specific: termination assertions apply only to declared finite rewrite domains with semantic state keys, and flow relations apply only where production CFG/value-flow evidence exists.

- Observation (M4): the mined fixture text does **not** engage the alias rule. `rust_apply_import_alias` rewrites only a `Namespace` binding with no imported name, and a path-form rename (`use a::b as c;`, the literal text of `9deded6f5`'s regression test) binds `c` as `Named` with `imported_name = Some("b")`. The rule fires on a single-segment rename (`use forc_pkg as pkg;`, the #1089 shape), which is what the binder records as a namespace rename. The mined test passed pre-instrumentation because it only asserts that a terminal status exists, which is trivially true when the chase never runs. The Milestone-4 fixtures therefore spell the same three shapes -- convergent chain, root-space rename cycle, long acyclic chain -- as single-segment renames, and the M0 probe constants keep the mined text with a comment recording this. Nothing about the resolver was changed to make the path form engage: that would be a resolution behavior change, out of scope here.
  Evidence: `crates/bifrost-rust/src/lexical_scope.rs:230-275` (`insert_rust_import_binding`) and `crates/bifrost-rust/src/graph_support.rs` (`rust_apply_import_alias`); the enabled fixtures in `code_query_flow_state_conformance.rs`.
- Observation (M4): `exceeded-budget` is *structurally unreachable* in this domain, and that is a property worth stating rather than a gap. Every rewrite consumes one distinct binder root and inserts it into the visited set, so the hop count can never pass the binder's root count; at the bound every root is visited, so the next state either repeats (cycle) or has no rule (converged). The guard stays in the production loop anyway -- the contract needs the terminal, and a second domain may well reach it.
- Observation (M4): the chase's declared bound needs one `import_binder_of` call, and that call is *not* memoized (it rebuilds from `import_info_of` every time). The bound is therefore computed lazily on the first successful rewrite, so a specifier that never engages the alias rule pays nothing, and an engaged chase pays one extra binder build on a path that already builds one per hop.
- Observation (M4): the framework/language reach-in gate (`tests/suite_cross_language/language_reach_in_gate.rs`) rejects the derivation naming `RustAnalyzer`. It is allowlisted rather than converted: a rewrite domain is *by declaration* a named production chase in one language, so a capability method would have exactly one implementor and would hide which language the domain claims. A second domain becomes a second arm; that is when a capability starts carrying information.
- Observation (M4): `rewrite-paths-of` needs no `WorkspaceAnalyzer` -- unlike the flow-state steps it reads no semantic artifact -- so its derivation takes `&dyn IAnalyzer` and works in every execution mode, including the analyzer-only entry points where `workspace` is `None`.
- Observation (M4): the JSON field label `outcome` was already claimed by `CandidateOutcomes` (the same collision class as M3's `class`/`relation`), so the wire field is `rewrite_outcome` while the RQL spelling stays `:outcome`. The `domain` label was free and is spelled identically in both frontends.

- Observation (M5): the completeness gate had to become **presence/absence asymmetric**, and the M2 fixtures forced the discovery. A relation the derivation states is a proven fact whatever else it could not enumerate; only a conclusion drawn from an *absence* needs the axis covered. Concretely: a read that a reaching row serves satisfies the assert with no coverage question, while "no establishment reaches this read" needs both the reaching axis and the read's own event axis covered, and a same-evaluation violation is reported even on a procedure whose same-evaluation axis is uncovered, while "no same-evaluation binder serves this read" is not. Without this the JavaScript `x = wrap(x)` fixture would have been inconclusive: its procedure reports the same-evaluation axis uncovered (a `Calls` capability gap) and still emits the relation.
  Evidence: `sameAssignment` reports `uncovered_axes: [same_evaluation_relation]` while `flow-relations-of :relation [same-evaluation]` returns the row.
- Observation (M5): a read in **return position does not join its identifier occurrence**. `const captured = early;` gives the read event the `ast_id` of the `early` identifier, and a capture on that identifier joins; `return value;` gives the read event a different arena node, so a capture on `value` joins nothing and the assert silently does not apply. Every Milestone-5 fixture therefore reads through a declarator initializer. This is an M2 site-anchoring limitation, not an assert one, and it is a follow-up candidate for Milestone 6: an assert whose capture cannot join is indistinguishable from an assert with nothing to say.

## Outcomes & Retrospective

Milestone 6 and plan closure (2026-08-12): the four things the Purpose section promised all work, and the two that do not are named rather than papered over.

What works. RQL enumerates binding and property state events per procedure, anchored to production CFG program points and joined to facts-arena `ast_id`s; it relates them as reaching (with `exact`/`may`), dominance and same-evaluation; it enumerates bounded rewrite paths for the `rust_import_alias` domain with per-step provenance and a `converged`/`cycle`/`exceeded-budget` terminal; and RQLP asserts both families with ordered witnesses and fail-unreliable propagation. Each of the four mined commits is named by at least one behavior fixture that runs -- `9e60fddcb` and `671e9b23b` as passing JavaScript same-evaluation and artifact-reach fixtures, `9deded6f5` as the cycle-witness rewrite row and the termination finding, `edb00e017` as a *documented honest negative* that asserts the typed adapter gap instead of a fabricated relation. No `#[ignore]` remains in any new suite. The acceptance criterion that matters most -- "structural containment and textual order are never presented as reaching proof" -- is enforced by construction rather than by review: `flow_state_for_file` acquires its evidence through `workspace.materialize_program_semantics`, the same call the `cfg-*` steps make, and the three relations are computed from `dominators`, `reaching_definitions`, and the IR's own `ValueFlow` dependence. No source-order comparison appears anywhere in the derivation; the only source bytes it touches are the member-name slice at an AST member locator's anchor span.

Gaps, all filed as follow-ups (#2013 Go assignment effects, #2014 return-position anchoring, #2015 JS/TS object-literal flow axes, #2016 resolver adoption of the flow relations). The Go adapter publishes no assignment effect for a `:=` range binder or a compound assignment, so `edb00e017`'s acceptance shape has no IR evidence to stand on. A read in return position anchors its state event at the return statement, so an RQLP capture on the returned identifier joins nothing and the assert silently does not apply -- the most dangerous class of gap this surface can have, because "not applicable" and "satisfied" look identical from outside. The JS/TS object-literal capability gap uncovers the reaching and dominance axes as well as the property axis, which is why the Milestone-5 property fixtures could not carry the temporal shapes end to end. And the resolvers whose hand-written order rules the mined commits added still decide by source bytes; a measured loop fixture shows them disagreeing with the relation this plan built. One rewrite domain exists, by decision, not by oversight.

Lessons. First: the strongest design move in this plan was refusing a second evidence source. Every difficult question -- can this read be served, is this write a kill, does this binder see itself -- was answered by asking what the production lowering actually publishes, and the answer was sometimes "nothing", which became a typed incomplete reason instead of a plausible row. The Go fixture is the proof that this discipline pays: the plan's own acceptance fixture reports a gap in Bifrost rather than a green check, and the test that pins it is the test that turns positive when the adapter is fixed. Second: presence and absence are not symmetric, and Milestone 5 only discovered this because a fixture forced it -- a stated relation is a fact whatever else went uncomputed, while a conclusion from an absence needs the axis covered. That asymmetry is now the contract, and it is the shape every future assert family in this kind should copy. Third: mined fixture *text* is not mined fixture *shape*. The `9deded6f5` regression test passes trivially against a chase it never engages, and it took instrumenting the production loop to notice; the M6 probe then showed the path form is correctly served by path arithmetic and needs no alias chase at all, so the inertness is a property of the mined test, not a resolver gap. Re-express a mined shape in the form the production code actually walks, and check that the fixture can fail.

## Context and Orientation

Bifrost is a Rust workspace. The crates relevant to this plan:

- `crates/bifrost-analysis`: per-language resolver and usage machinery (`analyzer/usages/get_definition/`), the structural facts arena and search execution (`analyzer/structural/`), the semantic IR with CFG/ICFG and its algorithms (`analyzer/semantic/`), and bounded dataflow (`analyzer/dataflow/`).
- `crates/bifrost-rql`: the RQL/CodeQuery language — declarative schema registry (`src/query/schema.rs`), typed IR (`src/query/ir.rs`), decode/validate, s-expression and JSON frontends.
- `crates/bifrost-core`: core types and the kind/role registries (`analyzer/structural/kinds.rs`).
- `crates/bifrost-policy`: RQLP — policy packs, the `assertion` analysis kind and its assert-family records (`src/schema.rs`), evaluators, finding/completeness accounting.
- `crates/bifrost-rust`, `crates/bifrost-js-ts`, `crates/bifrost-go`: split per-language crates; the Rust import binder and alias chase live in `crates/bifrost-rust/src/imports.rs`.

Terms used in this plan:

- A *program point* is a node of the production control-flow graph (CFG) that the semantic IR lowers per procedure (`analyzer/semantic/cfg.rs`); a *control edge* connects two program points. RQL already exposes both as typed rows via the `cfg-*` steps.
- A *facts arena* is the per-file flattened AST snapshot whose nodes carry stable content-scoped identities (`ast_id`); every typed row family from the sibling plans joins on those identities, and the new rows must too.
- A *state event* is this plan's new row: an establishment, kill/rebind, or read of a binding or property, anchored to a program point and an `ast_id`.
- A *flow relation* is this plan's new row family relating state events: reaching-definition, dominance, same-evaluation, each with `exact`/`may` certainty.
- A *rewrite domain* is a declared finite state space with a rewrite rule (first instance: import-alias roots under binder substitution); a *rewrite path row* records one bounded chase through it with per-step provenance and a terminal outcome.
- *Fail-unreliable* is the epic-wide soundness rule: any input the analysis cannot vouch for (unsupported axis, truncation, budget exhaustion, diagnostics, stale generation) makes a policy run `unreliable`/`Inconclusive` — never a clean pass, never a fabricated finding.

What exists that this plan builds on, verified in the survey: the `cfg-entry`/`cfg-exits`/`cfg-successor-edges`/`cfg-predecessor-edges`/`cfg-edge-source`/`cfg-edge-target` steps and the `ProgramPoint`/`ControlEdge` value kinds; `value-flow :plan-ref`, `typestate :protocol-ref`, `taint :taint-ref` and `witness` projection; budgeted stack-safe CFG algorithms (reachability, DFS order, SCC, loop regions, shortest path) over the `DenseBidirectionalGraph` view trait in `cfg_algorithms.rs`; the twelve assert families in `bifrost-policy/src/schema.rs`; the work-budget ledger vocabulary. What does not exist: dominance, reaching-definitions over the CFG, any state-event or kill/rebind row, any same-evaluation relation, any rewrite-path row, and any temporal or termination assert.

The Milestone-5 fail-unreliable mapping, as implemented:

| Input | Verdict |
| --- | --- |
| No workspace snapshot on the evaluation context (flow family) | `Inconclusive`, `CapabilityIncomplete` |
| No qualifying relation **and** the required relation axis (`reaching`/`dominance`) uncovered for the procedure | `Inconclusive`, `CapabilityIncomplete` |
| No qualifying relation **and** the read's own event axis (`binding_events`/`property_events`) uncovered | `Inconclusive`, `CapabilityIncomplete` |
| No same-evaluation row **and** `same_evaluation_relation` uncovered, under `:forbid-same-evaluation true` | `Inconclusive`, `CapabilityIncomplete` |
| No read event joins the capture **and** either event axis uncovered (includes a file that did not lower) | `Inconclusive`, `CapabilityIncomplete` |
| No read event joins the capture, both event axes covered | Skipped, exactly like `assert-binding-scope`'s absent binding |
| A relation the derivation states (reaching, dominance, or same-evaluation) | Conclusive, whatever else is uncovered |
| Rewrite derivation `NoDomainAnalyzer` / `NoIndexedSource` for the asserted domain | `Inconclusive`, `CapabilityIncomplete` |
| Rewrite derivation `Cancelled` | `Inconclusive`, `Cancelled` |
| `RewriteOutcome::ExceededBudget` | `Inconclusive`, `PartialDiscovery` -- never a finding, never a pass |
| `RewriteOutcome::Cycle` | Finding, with the ordered repeated-state witness |
| `RewriteOutcome::Converged` | Satisfied |
| `:scope` capture bound by no subject row anywhere | Run failure, `InvalidExecutionPlan` |
