# Procedure-summary model foundry (#1871)

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must remain current while implementation proceeds.

This plan follows `.agents/PLANS.md` from the repository root.

## Purpose / Big Picture

A procedure summary describes the value-flow behavior of one external procedure: which inputs (receiver, parameter N) reach which outputs (return, receiver, named heap or capture cells, exceptional return). The taint engine consumes summaries when a call target's body is unavailable, which is true for every standard-library call. Today the pipeline that consumes summaries is wired end to end (`bind_compiled_procedure_summaries` in the semantic-model runtime, `ExternalSemanticSummarySet`, `ValueFlowPlan::with_external_summaries`, proven by the Java vertical in `.agents/plans/activate-semantic-pack-taint-summaries.md`) but almost no summaries exist. A taint policy over real code must therefore either over-approximate through every stdlib call (`paranoid` mode, noisy) or fail closed (`require-model` mode, cannot conclude). Either way it cannot both terminate cleanly and stay precise.

After this change, a maintainer can run one command per language ecosystem that produces a reviewed, versioned, proof-carrying summary pack for a pinned standard-library edition, and re-run the same command when a new edition ships with human attention required only on the delta. The observable outcome: a `require-model` taint policy over a fixture that flows attacker-controlled data through a summarized stdlib API yields a finding with a witness and a `ProvenBySummary` completion when the pack is active -- a conclusion that is neither `Inconclusive` nor `Complete`, because the run is precise and terminating but rests on authored external models rather than on analyzed code (#1916) -- and the honest typed incomplete outcome when it is not; and a corpus sweep reports the fraction of taint verdicts that conclude cleanly, which must rise as packs land.

The factory is called the foundry in this plan. It is a pipeline of five stages per module (a module is one stdlib namespace, for example `java.lang` or Python's `os`), executed depth-first per module, with every stage artifact persisted and content-addressed so the pipeline is resumable and individual stages can be edited and re-run without redoing the others.

## Design constraints (from the 2026-08-09 design discussion)

Activation cost and retained memory are not constraints: measured JDK-scale activation is ~5.5 s cold and ~14 MB retained for declaration facts, accepted, and SQLite-backed storage work landing separately will reduce residency further. The binding constraints are precision at native and dynamic boundaries, review attention (the human review surface must be roughly a dozen decisions per stdlib edition, not a hundred), trust (every shipped claim must carry machine-checkable evidence), and maintainability (a new stdlib edition is one pin update plus a delta review).

## Architecture

Stage 0, pinned inputs. Each ecosystem has a pinned source artifact (the JVM uses Temurin `src.zip` plus `kotlin-stdlib` and `scala-library` source jars pinned by sha256 in `scripts/build-pinned-jvm-semantic-packs.sh`; Python uses the typeshed revision pinned in `semantic-packs/python/typeshed-stdlib-*.json`), the external model corpora normalized into our summary IR (CodeQL Models-as-Data first, MIT-licensed, deepest for Java and C#; Joern semantics second, Apache-2.0, as a lighter cross-check), and a demand ranking produced by running the repository's taint policies in `require-model` mode over the benchmark corpus (the FIRD clone fleet) and aggregating the typed unmodeled-call blockers by how many verdicts each blocks.

Stage 1, deterministic derivation. Our own analyzer runs over the pinned bodies at generation time and emits candidate summaries in the authored IR (`AuthoredProcedureSummary` in `crates/bifrost-analysis/src/analyzer/semantic_model/model.rs`: exact target with artifact path, symbol, receiver-ness and parameter count; transfers; effects; a completeness claim). The derivation must type its own incompleteness per entry using the boundary-status machinery: when a body bottoms out in a native method, reflection, or an unresolvable call, the entry records that typed reason. No LLM is involved in this stage.

Stage 2, corpus alignment. Translators convert CodeQL Models-as-Data rows and Joern semantics entries into the same IR. A three-way join per target classifies each entry: all sources agree (high confidence), sources disagree (a dispute record), or only one source covers it (a gap record). Where our derivation has no answer and CodeQL does, the CodeQL entry is imported directly with provenance and attribution recorded. Everywhere else the external corpora act as standing verification oracles, re-checked on every foundry run, never a one-time import.

Stage 3, LLM adjudication, minimal by construction. Routing follows stage 1's typed incompleteness: fully derivable entries never see an LLM; underivable entries covered by CodeQL are translate-and-verify, no LLM; only entries that are both underivable and uncovered enter LLM proposal, plus dispute repair. The harness hands the model the pinned source body, documentation from the source artifact, the partial derivation with its typed incompleteness, and any oracle entries for neighboring overloads. The calibration discipline is strict: the model proposes blind first; first-pass agreement against the CodeQL overlap (stratified by difficulty class: native-boundary versus pure code, arity, receiver-ness) is the recorded trust metric; only after grading does the mismatch detail return to the model as a self-correction signal, after which it either concedes and repairs or produces a refutation dossier. Bulk proposals run on a smaller model; disputes and anything touching sanitization escalate to a stronger model. The model has no shipping authority: its output must survive stage 4.

The calibration data comes from a dedicated grading pass, because production routing alone would never produce it: shipped LLM output exists only where CodeQL is absent, so the harness additionally runs the model blind over the underivable-but-CodeQL-covered stratum purely to be graded. Those proposals are never shipped (the CodeQL translation ships for that stratum); they exist to measure first-pass agreement, and they re-run at every edition so the trust metric stays current. A graded proposal that maintains disagreement with CodeQL through the correction loop becomes a refutation dossier that cross-examines the corpus entry we were about to import, so the calibration pass doubles as an audit of the imported corpus.

Stage 4, proof gates. Every entry ships only with machine-run executable evidence generated mechanically from the IR by a per-language fixture template engine, never by the proposing model. A positive fixture proves each claimed transfer carries taint with the pack active and fails with the entry absent (the fail-before control). For entries claiming `complete`, a negative fixture proves taint does not cross where the summary says it does not, which is provable under `require-model` because the summary is then the only model in play. Fixture generation scales with the corpus because it is a deterministic function of the record.

Sanitizer fixtures must be adversarial, not benign. A sanitizer entry claims that a method neutralizes taint for a named injection context (`sql`, `shell`, `ldap`, `xpath`, `html`, and the rest of the fixed vocabulary). A positive sanitizer fixture must inject that context's actual breakout metacharacter and prove the method encodes or removes it, and, for every context the entry lists under `does_not_neutralize`, a fixture must prove the breakout for that context still flows. A fixture that flows a benign payload would rubber-stamp a wrong claim: this is not hypothetical, it is the exact failure the first sanitizer batch produced, where six URL and URI percent-encoders were proposed as `sql`/`shell`/`ldap`/`xpath` sanitizers because their surviving unreserved characters (`-`, `*`, `~`, and the `%` and `_` in percent-encoded output) are metacharacters in those grammars while a benign string would have encoded cleanly. The per-context breakout-metacharacter table therefore lives in the fixture engine, one entry per vocabulary token, and a sanitizer that cannot be proven against its claimed context's metacharacter is rejected, never shipped on the author's assertion.

Stage 5, assembly and audit. Packs build through the existing pinned-spec pipeline in `crates/bifrost-semantic-packs` (license, provenance, semantic hashes, rejects reporting, measurements). Two corpus-level audits close the loop: the demand sweep re-runs and reports the percentage of taint verdicts concluding cleanly (the acceptance metric), and a pack-on versus pack-off diff over the fleet lists every finding that disappears with the pack active, mechanically attributed to the suppressing entry in its trace. That diff is the only gate that can see silent false negatives, the failure mode per-entry proofs cannot.

## Trust and the human review surface

Entries default to `completeness: partial`. A partial summary can add flows but can never prove absence, so a wrong one produces at worst a visible false positive, never a silent miss; these auto-ship on ensemble agreement plus proofs. Suppression power exists only in sanitizers and `complete` promotions, so the human queue is exactly the demand-ranked promotion list: the top roughly ten entries per stdlib edition by verdicts unblocked times suppression power, each arriving with its dispute dossier and both-polarity proofs. Beyond that queue the human surface is one pilot-module report and one batch-audit verdict (a random sample of auto-shipped entries whose measured error rate validates or rejects the whole batch). Escalation to a human happens for one reason only: the strong model reviewed a CodeQL discrepancy, maintains CodeQL is wrong, and presents fixture evidence. Each such dossier is either a foundry bug to fix or an upstream CodeQL model bug worth filing.

## Execution model

Every (module, stage) artifact is a file in a foundry work directory, keyed by the hash of its inputs: the pinned source slice, the stage code version, the prompt version, and the upstream artifact hash. A re-run skips any artifact whose key is unchanged, which makes interruption resumable at no cost and makes editing one stage (for example a prompt) invalidate exactly that stage and its downstream. Modules run depth-first, all five stages to a finished module report before the next module begins, in demand order, so the pilot module a human sanity-checks is also the highest-value content. Scaling after the pilot is parallel module workers, each still depth-first. The work directory is git-committable so review and edition-over-edition diff are the same operation.

## Language calculus

CodeQL covers nine of our eleven languages (all but Scala and PHP), so calibration is available almost everywhere, with corpus depth best in Java and C# (translation bootstrap), moderate in JS/TS and Python, thin in Go, Ruby, C++ and Rust (calibration only, sampled audit carries more weight). Scala needs no separate JDK work because JVM summaries target artifact path and symbol, not a language, and the JVM realm already serves Java, Kotlin and Scala together; the residual is `scala-library` content through the same foundry. PHP receives no summary content until demand appears; `require-model` taint over PHP then reports honest typed incompleteness, which is a shipping posture, not a removal.

## Milestones

Milestone 1, the IR seam and translators. Extend or wrap the authored IR as the foundry's interchange form, write the CodeQL Models-as-Data translator and the Joern semantics translator, and the three-way join with dispute and gap records. Acceptance: translating the CodeQL Java corpus produces a count of well-formed entries, a dispute list against the Joern translation, and every translated entry round-trips through `compile_source` in `crates/bifrost-analysis/src/analyzer/semantic_model/compiler.rs` without error.

Milestone 2, deterministic derivation with typed incompleteness. Implement generation-time summary derivation over pinned JVM sources, reusing the analyzer's value-flow machinery, emitting per-entry typed incompleteness. Acceptance: for a chosen pure-Java class the derived transfers match the CodeQL translation exactly; for a native-backed class the entry records the native boundary rather than guessing.

Milestone 3, the fixture engine. A deterministic generator that, from any IR entry, emits a compiling per-language fixture pair (positive with fail-before control; negative for `complete` claims) and a runner that executes them through the production policy path. Acceptance: the generator produces passing fixtures for twenty hand-picked known-good entries and correctly fails a deliberately corrupted entry.

Milestone 4, the foundry driver and adjudication harness. The content-addressed (module, stage) store, depth-first module scheduling, resumability, and the blind-then-graded LLM loop with first-pass calibration recording. Acceptance: interrupting a module run mid-stage and re-running completes without repeating finished stages; editing a prompt version re-runs only stage 3 and later; the calibration report shows first-pass agreement stratified by difficulty class.

Milestone 5, the Java pilot. Run the foundry over the top-demand JDK modules end to end, produce the pilot module report, the promotion queue, and the batch-audit sample, and take the human decisions. Acceptance: the #1871 vertical shape passes against foundry-produced content, and the demand sweep's clean-conclusion percentage rises measurably from its pre-pack baseline.

Milestone 6, audits and scale. The pack-on/off fleet diff with suppression attribution, the measured batch error rate, then parallel module workers across the remaining JDK and the first non-JVM ecosystem (Python via typeshed pins) to prove the foundry is not Java-shaped. Acceptance: the fleet diff report exists and every disappearing finding traces to a reviewed suppressing entry; the Python run reuses the same driver with only ecosystem adapters changed.

## Surprises & Discoveries

- The 2026-08-09 epic acceptance probe (#1893, closed) proved the boundary-status machinery can type a derivation's own incompleteness, which is what makes no-LLM routing decidable per entry.
- Joern ships no `.semantics` resource file at the pinned revision. The default corpus is Scala source, `dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/DefaultSemantics.scala`, and `javaFlows` holds only 23 entries. The foundry therefore has two Joern front ends over one value: a parser for the documented `.semantics` DSL (grammar `Semantics.g4`) and a reader for the pinned Scala list literal. The Scala reader fails loudly on any shape it does not know, so an upstream refactor stops a foundry run instead of quietly translating less.
- The authored IR carries less than the corpora state, in three ways that milestone 2 must weigh:
    - It has no output port for a write into parameter N. 132 CodeQL rows and all 23 Joern mappings that were skipped want one (Joern's `getChars`-style buffer writes and every `(1,1)` self-taint mapping).
    - It has no access paths. 3672 CodeQL rows qualify a port with `.Element`, `.MapValue`, `.MapKey`, `.ArrayElement`, `.SyntheticField[..]`, `.Field[..]`, or `.Parameter[..]`. `.SyntheticField[..]` and `.Field[..]` on an output look directly expressible as the existing named `heap` location; the container qualifiers do not, because an authored input can only be the receiver or a parameter.
    - It cannot state "no flow at all". `validate.rs` rejects a summary with no transfer and no effect (`summary.empty`), so 771 CodeQL `neutralModel` summary rows and every Joern nil semantic translate into the foundry IR and stop there. These are exactly the claims with suppression power, so the shape they need is the same one the plan reserves for the human promotion queue.
- CodeQL and Joern share almost nothing on the JVM. Of 3418 join keys, one is comparable and it is a dispute: CodeQL states `java.lang.String.compareTo(String)` is neutral, Joern states `receiver -> receiver` through `PASSTHROUGH`. Joern is not a cross-check of CodeQL's JVM content at this scale; it is a second opinion on about twenty targets. The plan's "lighter cross-check" framing holds, but the calibration weight it can carry for Java is near zero.
- Three CodeQL rows reference an argument ordinal their own pinned signature does not have: `com.google.gson.Gson#toString()` with `Argument[0]`, `io.netty...ServerCookieEncoder#encode(String,String)` with `Argument[1..2]`, and `javax.naming.directory.BasicAttributes#put(Attribute)` with `Argument[0..1]`. Two more targets carry both summary rows and a `neutralModel` summary row. The translator records both as typed findings rather than guessing; they are candidate upstream bug reports.
- Models-as-Data carries `barrierModel` and `barrierGuardModel` extensibles (31 rows in the Java corpus) that the plan did not name. They are counted as out of scope, like sources and sinks.
- The Java lowering did not connect a conditional expression to its branches (found by milestone 2, 2026-08-09). `(c) ? a : b` produced a fresh value with no incoming flow, so `return (obj != null) ? obj : requireNonNull(defaultObj, "defaultObj");` derived nothing at all. In a taint query that is a false negative; in a derivation it is worse, because there is no boundary to explain it and a fully traversed body could have claimed `no_flow`. Each branch now leaves through its own merge point that carries the one flow into the conditional's value. The merge point exists because the flow has to be ordered after the branch produced its value, and the branch's own effects land on the points between its entry and the merge.
- The analyzer had no notion of a `native` declaration anywhere (found by milestone 2, 2026-08-09). `callable_shape` drops any Java method without a body, so a native method produces no procedure at all, and at the call site a native callee, an abstract method, and an interface method all collapse to one `DispatchBoundaryKind::Unmaterialized` with the same reason string. Milestone 2's acceptance requires telling them apart, so Java's callable-modifier reader now records `native` beside `static` and `SignatureMetadata` carries it. Nothing else consumes it yet.
- A boundary locator and a procedure locator name a declaration differently. The semantic inventory spells a method `[File, Type.., Method]`; the dispatch resolver spells the same declaration `[File, Function]` with no owning type. The derivation's declaration index is therefore keyed by (file, member identifier), and the owning type comes back from the declaration rather than from the locator.
- The value-flow oracle reports no access path beneath a parameter port for Java today. A field read of a parameter (`return box.value;`) yields an `unsupported` heap capability rather than a `parameter[0].Field[value]` carrier, so the derived fine-grained slot currently equals its argument-level projection. The seam is built for the finer form anyway (sources and sinks bind access-path carriers, and `FoundryAccessPath` keeps the selectors), so heap sensitivity turns it on without a redesign. The important property already holds: the entry records the typed semantic gap and stays `partial` instead of answering `no_flow`.
- Reflection does not identify itself. `java.lang.reflect.Method.invoke` is ordinary Java that calls an interface method, and `Array.get` is native, so a `reflective_call` boundary would be a curated name list rather than an observation. Milestone 2 therefore records what it saw -- `native_callee`, `callee_without_body`, `external_callee` -- and leaves reflection to be recognized where a name list can be reviewed as content.
- The derivation's yield is dominated by the workspace boundary, not by the analyzer. Over `java.util` alone, 4948 procedures produced 165 transfers, and the largest boundary counts are `semantic_gap` and `unresolved_call`, followed by `callee_without_body` and `external_callee`. That is the expected shape when `java.lang`, `jdk.internal`, and the rest of `java.base` are outside the indexed set: almost every interesting callee is external. The measurement to take before drawing any conclusion about derivation power is the same run over the whole extracted `src.zip`, where those callees resolve.
- One derived target costs a full closure rediscovery. The derivation re-walks the oracle for every target, with no memoization between targets, so `java.util` took about 31 minutes on one core for 4948 procedures. Milestone 4's content-addressed (module, stage) store is where that stops being paid twice; nothing here should be optimized before the store exists, because the store changes what is cached.
- The packs document does not carry procedure summaries into the CLI's taint route (found by milestone 3, 2026-08-09). `.bifrost/packs.json` activation runs through `activate_workspace_packs`, which publishes declaration facts into the workspace snapshot; the taint evaluator's summary binding instead reads `PolicySemanticModelContext`, which only an API caller supplies. `evaluate_policy_inputs` -- the entry point the CLI, the MCP host, and the LSP host all use -- passes `None`. A measured probe confirms it: the same fixture with the pack installed in the workspace catalog, the packs document opting into `jvm`, and the pack reported `selected` in the report's `packs.decisions`, produced zero findings through the CLI and one finding through `evaluate_policy_inputs_with_analyzer_and_semantic_models`. The plan's Purpose sentence therefore describes an API-supplied activation today, not a workspace-document one. This is the gap milestone 5 has to close before "the #1871 vertical shape passes against foundry-produced content" can mean anything to a user, and it deserves its own issue.
- A `require-model` taint run that binds an external pack summary can never report `Complete` (found by milestone 3, 2026-08-09), and #1916 resolved it with a new completion tier rather than by relaxing `Complete`. `bind_compiled_procedure_summaries` correctly stamps every external transfer unproven, because a summary is an authored assertion about a body Bifrost never analyzed, and `ValueFlowPlan::model_is_fully_bindable` requires proven *and* complete, so `Complete` is unreachable through summaries by design. Rather than making an authored claim satisfy the word reserved for proof from analyzed code, the run now concludes at `PolicyRunCompletion::ProvenBySummary`: it ranks below `Complete` and above `Inconclusive`, it earns its precision only when authored-complete external summaries close every open boundary, and it degrades to `Inconclusive` the moment any boundary is genuinely unmodeled (no summary, a partial summary, or a truncated collection). The signal is computed structurally by `ValueFlowPlan::execution_result_complete_accepting_authored_summaries` and surfaced through `TaintFindingReport::is_proven_by_authored_summaries`. Milestone 3's positive gate over a `complete` entry now asserts `ProvenBySummary` end to end, its fail-before control asserts `Inconclusive`, and a partial-summary positive still asserts `Inconclusive`; the negative case a `complete` entry carries now reports `ProvenBySummary` too, which is what makes its zero-finding denial a genuine (authored) claim rather than a vacuous one. The separate reasons a fixture sink or source must be a bodyless declaration -- a sink with a body loses the finding entirely, measured -- are #1917 and stay out of this fix.
- A Models-as-Data row without a signature cannot be proof-gated at all (found by milestone 3, 2026-08-09). Its authored symbol is the bare member name, and the exact external target a Java call site publishes is always `identifier` plus a parenthesised parameter signature, so no declaration can produce a matching symbol and the binder has nothing to bind. That is the same unsigned-row problem the milestone-2 retrospective raised about join keys, arriving from the other end: an unsigned row is not merely hard to compare, it is unshippable as written. Six of the eight flow-carrying entries the pinned CodeQL slice produces are unsigned.
- A taint sink declared with a body observes nothing (found by milestone 3, 2026-08-09). The same fixture, same policy, same summary: with `static native void sensitive(String)` the run reports one finding, and with `static void sensitive(String value) { }` it reports none. A source with a body is unaffected. Every existing test in the fleet happens to declare native sinks, so nothing covered this. It is recorded here as an observation with a reproducer, not diagnosed; the fixture engine sidesteps it by declaring native helpers.
- The first run over a real `java.util` slice stopped twice on conditions the fixture tests could not reach, and both are analyzer findings rather than foundry ones. `java.util.Arrays.toArray` produces a `ValueFlowPlan` that rejects its own carriers with `StableCarrierCollision`, which means a taint query over that body is refused the same way. `java/util/ArrayList.java` fails semantic materialization outright with `constructor callable cannot carry a bound receiver`, a method-reference lowering that violates the IR contract. Neither now stops a run: a refused target becomes one entry with an `engine_rejected` boundary, an unmaterializable file is recorded in `unavailable_files` with the provider's own reason, and both are counted so the next run measures them. Both deserve their own issues.

- Depth-first per module with content-addressed stage artifacts, in demand order (jbellis, 2026-08-09).
- The trust signal requires a dedicated blind grading pass over the underivable-but-CodeQL-covered stratum, with outputs discarded from shipping; production routing alone generates no calibration data. Spotted by jbellis after Milestone 1 dispatch (2026-08-09).
- Milestone 1 wraps the authored IR instead of extending it (Fable, 2026-08-09). `AuthoredProcedureSummary` is the shipping contract that the compiler and the runtime binder consume; provenance, uncarried-claim notes, and the no-flow claim are foundry state, not shipping state. `FoundryEntry` holds both and projects the shipping contract back out. Extending the authored IR with a no-flow claim changes runtime semantics and belongs with the milestone where a proof gate can test it.
- Translation skips faithfully instead of coarsening (Fable, 2026-08-09). Reading `Argument[0].Element -> ReturnValue` as `parameter[0] -> normal_return` would be a sound over-approximation for a partial summary, but it silently restates the corpus and would make the milestone-2 derivation agree with a claim CodeQL never made. Every unrepresentable row is counted under a typed reason instead.
- The join key is (class-file path, member, pinned arity) (Fable, 2026-08-09). The corpora spell parameter types differently (`(String)` against `(java.lang.String)`), so arity is the only signature projection that compares. A row with no signature pins no overload, so it takes its own key with `arity: null` rather than acting as a wildcard that could manufacture agreement; gap records name the sibling arities so a reviewer sees the neighbourhood.
- Constructors normalize to `<init>` and packages to class-file paths (Fable, 2026-08-09). Models-as-Data names a constructor after its type and Joern names it `<init>`; both reduce to the JVM binary spelling, which is also what an authored target's `path` and the eventual artifact resolution use.
- `semantic-packs/summary-corpora/pins.json` is the single source of truth for both the acquisition script and the join tool (Fable, 2026-08-09), so a revision bump is one edit and a report can never claim a revision the download did not use. The corpora themselves are not vendored; only small verbatim slices under `crates/bifrost-semantic-packs/testdata/summary-corpora/` keep translator tests offline.
- The artifact that holds a class is a typed `FoundryArtifactBinding::Unresolved` on every translated entry (Fable, 2026-08-09). Neither corpus names an artifact and the foundry has no artifact index yet, so the field records the gap where the answer belongs instead of guessing a jar.
- External corpora are demoted from a source of shipped content to a demand prior plus a calibration oracle at the coarse projection; nothing translates directly into shipping content (David, 2026-08-09). Stage 2's import path in the architecture section is superseded by this: a CodeQL row informs what to derive and grades what was derived, and shipping content comes from derivation and, where derivation cannot reach, from adjudicated proposals that survive stage 4.
- The IR's direction of travel is heap- and object-sensitive compositional summaries, with global side effects deferred (David, 2026-08-09). Field-level distinctions on a parameter are the next granularity the shipping IR must carry; whole-program global effects are explicitly not on the path yet.
- A sustained dispute becomes a regression test or a tracking issue, never a silent divergence (David, 2026-08-09). A dispute that survives repair is evidence about one of the two sources and has to be recorded where it can be re-checked.
- Milestone 1's 3672 `access_path_unsupported` skips are the concrete evidence for the granularity direction (David, 2026-08-09). They are not corpus noise; they are the shape the shipping IR is missing, and they are why milestone 2 must not collapse granularity at the derivation seam.
- The derivation preserves granularity at the seam and projects only at the end (Fable, 2026-08-09). Sources and sinks bind access-path carriers, not only bare ports; `FoundryDerivation::fine_grained` keeps every derived flow with its selectors, and `FoundryEntry::transfers` is that set projected onto its two ports. The projection is irreversible, so it happens once, in one place, after the answer is known.
- A summary-backed `require-model` run concludes at a new `ProvenBySummary` tier, not `Complete` (#1916, 2026-08-09). The maintainers chose Option B: a run whose only open boundaries are authored-complete external summaries is precise and terminating, but its precision rests on authored models rather than on analyzed code, so it earns a tier that ranks below `Complete` and above `Inconclusive` instead of being promoted into the top word. Rationale: `bind_compiled_procedure_summaries` stamps every external transfer unproven by design, because a summary is an authored assertion about a body Bifrost never analyzed; relaxing `Complete` to accept that stamp would let authored trust masquerade as proof from analyzed code, which is exactly the honest-epistemics property `require-model` exists to protect. The tier passes the exit gate (it does not exit `unreliable`, and a zero-finding summary-backed run may exit clean) but stays distinct and visible in the human and SARIF renderers, so a consumer may treat it as a warning. It is not exhaustive: suppression and baseline absence still require `Complete`, because absence proven only under authored trust is not absence proven from code. The tier is earned only when authored-complete summaries close every open boundary; a partial summary, a missing summary, or a truncated collection degrades the run to `Inconclusive`.
- The join compares at the argument-level projection and says when a match holds only there (Fable, 2026-08-09). Models-as-Data rows and the authored IR are both argument-level, so the projection is the only granularity every slot can state. `FoundryAgreement::at_projection_only` marks an agreement where a slot knew more, and every claim view carries the finer flows and the typed boundaries beside the compared form.
- The derivation walks the call closure itself instead of reusing the taint policy's `discover_value_flow` (Fable, 2026-08-09). The two have opposite contracts: the policy aborts on the first interrupted oracle outcome, because a verdict must not rest on a partial input, while the derivation records the interruption as typed incompleteness on the entry and continues, because a partial derivation that names its boundary is the artifact this stage ships. Sharing them would need a mode flag on the one behavior that differs.
- The derivation binds output sinks at the write, not at the exit point (Fable, 2026-08-09). A procedure has exactly one normal and one exceptional exit point, but neither is ever the source of an edge the solver evaluates, so a sink bound there never fires. The snapshot states each write's exact point, which is also the point whose local rule makes the port carrier live.
- The derivation runs with `UnmodeledCallBehavior::RequireModel` (Fable, 2026-08-09). `Paranoid` would manufacture a transfer through every unmodeled call, which is exactly the guess the milestone forbids; `Optimistic` would preserve facts and stay silent about the call, which reads as a derivation that saw the body. `RequireModel` abstains, and the abstention is what the typed boundary then explains.
- Milestone 2 observes the return ports only (Fable, 2026-08-09). A receiver, capture, or heap output states that the callee mutated memory reachable from an input, which needs the heap oracle this stage does not drive. The derived slot is therefore silent about those outputs rather than denying them, and the report names the ports it did observe so the silence is visible.
- Derived entries default to `partial` and may claim `complete` only when the traversal met no boundary at all (Fable, 2026-08-09). `no_flow` requires the same condition, because only a fully traversed body can deny a flow; every other empty result is a `flows` entry with no transfers and a typed reason.
- The pinned JDK slices are reduced verbatim, kept out of the published crate, and recorded in `PROVENANCE.md` (Fable, 2026-08-09). Temurin `src.zip` is GPL-2.0 WITH Classpath-exception-2.0 and this workspace is LGPL-3.0-or-later, so `testdata/summary-sources/**` is excluded from packaging; the slices keep their upstream copyright headers and one labelled slice marker, and every other retained line is byte-identical.
- A derive-locally tier joins the pack tier (jbellis and Fable, 2026-08-09). A workspace derives its dependencies' summaries at index time from sources jars, through a new coordinates-to-sources.jar resolver that reads the local cache first and fetches only on a miss, and emits the same pack format cached by content hash. Published packs then narrow to the native floor, the sanitizer overlay, and reviewed cold-start or enterprise editions. Milestone 2's `derive_jvm_summaries` is the shared engine for both tiers: it already takes a source root and a limits budget and returns entries with typed incompleteness, so the tier difference is where the sources come from and where the result is cached, not what runs.
- The fixture proves executability, not truth (Fable, 2026-08-09). A procedure summary binds only where the workspace holds a declaration *without a body*, so a fixture can never contain the target's real body and can never check a claim against it. What a fixture states is that the entry's transfer set, applied to a target of the shape the entry itself declares, survives the production pack compiler, binds through the production binder, carries taint to the sink through each claimed port, and does not carry it when the entry is absent. Truth stays stage 1's and stage 2's question. The corruption class this gate catches is therefore a shape corruption -- a transfer naming a port the target does not have -- and not a wrong-but-well-shaped transfer, which is undetectable by construction in a synthetic fixture.
- The generator never pre-judges a claim it can render (Fable, 2026-08-09). It widens its own declaration so every input port the entry mentions has a call-site slot, and ships the entry's declared parameter count verbatim in the pack. A disagreement between the two is the entry's to answer for, and `compile_source` is what answers it. A generator-side ordinal check would have moved the verdict out of shipping machinery and into the fixture engine, where a reviewer cannot see it.
- The pack symbol is the language's spelling, not the entry's (Fable, 2026-08-09). The corpora join parameter types with a bare comma and the Java declaration walk joins them with a comma and a space, so a symbol copied from the entry fails to bind for every target of arity two or more, silently. `FixtureLanguage::symbol` owns that spelling for its language and is the seam a second language implements together with the declaration renderer.
- The runner lives in the facade (Fable, 2026-08-09). It needs the foundry IR from `brokk-bifrost-semantic-packs` and the evaluator from `brokk-bifrost-policy`, and `scripts/check-workspace-dependencies.mjs` deliberately keeps the packs crate below policy. The facade is the only package that depends on both. A milestone-4 driver that wants stage 4 has to call it from there, or shell out.
- The fixture runs through the policy registry API rather than the CLI (Fable, 2026-08-09). The CLI route was measured first and cannot carry procedure summaries at all (see the discovery above), so `evaluate_policy_inputs_with_analyzer_and_semantic_models` is the only production evaluation route through which a summary reaches the taint engine today. No `.bifrost/packs.json` is written into a fixture, because a document that changes nothing about the run would be decoration.
- Only a `complete` entry gets a negative case, and a pure no-flow claim gets none (Fable, 2026-08-09). Milestone 1 established that a no-flow claim has no authored spelling, so it cannot be compiled, activated, or executed; the negative polarity is therefore exercised by `complete` entries that do carry transfers, whose unclaimed input ports are the routes a complete claim denies. The plan's "no-flow/complete entry" requirement is read as "an entry whose claim can deny", which is exactly the `complete` set.
- `FoundryEntry` carries the completeness claim and `FoundryDerivation` no longer does (Fable, 2026-08-09). The claim belongs to the entry because an entry reaches it through derivation today and through adjudication or review later, and stage 4 must read it without knowing which. The derivation keeps its boundaries, which are the evidence for the claim rather than the claim itself. `FoundryEntry::authored_summary` now projects the claim instead of hardcoding `partial`; the builder still produces `partial`, because translation is not traversal.
- Decompilation is deferred behind a measurement (jbellis, 2026-08-09). The demand sweep's typed blockers join to their declaring artifacts and bucket by sources availability; the share of blocked verdicts owned by the jar-without-sources bucket decides whether any decompiler or bytecode machinery is ever built. Nothing in that direction starts before the number exists.

## Outcomes & Retrospective

Milestone 1 is done and its acceptance holds. Two observations shape what comes next.

The first is that the authored IR, not the corpora, is now the binding constraint. Of 7128 CodeQL summary rows, 3425 transfers survive translation; the 3672 rows lost to access paths and the 132 lost to parameter-write outputs are not corpus noise, they are three specific missing shapes. Milestone 2 should decide which of them the derivation will need to emit anyway, because a derived summary of a real JDK body will want to say "the elements of the argument reach the return" just as often as CodeQL does.

The second is that Joern cannot serve as the JVM cross-check the plan assumed. One comparable target out of 3418 is not calibration. The verification role the plan gives the external corpora has to rest on CodeQL alone for Java, with Joern retained for the languages where its corpus is comparatively deeper, and the milestone-3 proof gates carrying correspondingly more weight.

Milestone 2 is done and its acceptance holds. Three observations shape what comes next.

The first is that the derivation's precision is bounded by the analyzer, not by the design, and the two gaps it hit were both silent. A conditional expression carried no value flow at all, and a native callee was indistinguishable from an abstract one. Both were fixed at the root rather than worked around, and both were invisible until something asked the analyzer to answer for a whole standard library instead of for one query. That is the strongest argument for running the derivation over the full pinned JDK early: every remaining gap of this shape is a false negative in some taint verdict today, and the foundry is the instrument that finds them.

The second is that granularity is now the open question the shipping IR has to answer. The derivation keeps access paths, the join compares projections, and the report counts what the projection dropped -- but the value-flow oracle currently reports no path beneath a Java parameter port, so that count is zero and will stay zero until heap sensitivity lands. The plumbing being in place is what makes the eventual change small; the measurement being zero is what makes it honest to say the derived slot is argument-level today.

The third is that the derived slot mostly produces gaps rather than agreements against CodeQL, and for a structural reason: Models-as-Data usually pins no signature, so its key carries `arity: null` while a derived entry pins the exact overload. The transfers match; the keys do not. The `java.util` run makes this concrete: 7682 gaps, 0 agreements, 0 disputes. Milestone 3's fixture engine works per entry and is unaffected, but the demand ranking and the promotion queue both read the join, so the reviewer-facing question "does our derivation agree with CodeQL here" currently has to be answered through the gap records' sibling keys rather than through the agreement count. Deciding how an unsigned corpus row compares against an exact overload is the first thing milestone 3 or 4 has to settle, and it is a judgement about what "agreement" should mean, not a bug. Milestone 3 did not settle it and left it untouched; it did add one fact to the file, from the other end of the pipeline: an unsigned row is not only incomparable, it is unshippable, because its symbol names no exact procedure and the production binder can never bind it.

Milestone 3 is done and its acceptance holds. Three observations shape what comes next.

The first is that the proof gate is real but narrow, and its narrowness is structural rather than incidental. A summary binds only against a bodyless declaration, so a fixture is always synthetic and can only ever prove that a claim is executable and load-bearing. Every corruption class that a synthetic fixture can catch is a shape corruption. That is not a weakness to fix in stage 4; it is the reason the plan puts truth in stages 1 and 2 and puts the false-negative question in stage 5's fleet diff. What stage 4 buys is that no entry can ship without having been compiled, bound, and executed, and that is worth having on its own.

The second is that two of the plan's own promises are not reachable through the product as it stands, and both were found by trying to execute them rather than by reading. `.bifrost/packs.json` does not deliver procedure summaries to the CLI (#1915), and a `require-model` run that binds an external summary could not report a clean conclusion. The second is now resolved: #1916 added `PolicyRunCompletion::ProvenBySummary`, so the Purpose sentence names that tier rather than `Complete`, and a summary-backed run concludes precisely without laundering authored trust into the word reserved for proof from analyzed code. The CLI-activation gap remains milestone 5's work under #1915.

The third is that the fixture engine is a good instrument for finding engine gaps, exactly as the derivation was in milestone 2. Three of the four discoveries above came from a fixture that did not behave as it should have, and one of them -- a taint sink with a body observing nothing -- is a plain false negative that no test in the fleet covered because every existing fixture happens to declare native sinks. Running the generator over a wider slice of the corpus, before milestone 4 needs it, is likely to keep paying.
